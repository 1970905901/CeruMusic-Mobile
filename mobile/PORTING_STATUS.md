## 架构与约定

- 移动端是独立工程，不启动 Electron 主进程。
- 前端栈：Vue 3 + TypeScript + Ionic Vue + Capacitor 7。
- 插件代码在 Web Worker 中运行，宿主能力通过 JSON RPC 暴露。
- 插件逻辑不直接访问网络、存储、播放器等宿主能力；必须经 Worker -> Host RPC。
- iOS 使用 Ionic iOS 模式、安全区、版本化 CSS 类；不是 SwiftUI/UIKit 原生控件逐版本实现。
- Android 使用 Material 模式；平板/分屏布局在 `src/theme/tablet.css`。
- 不要把 token、Cookie、密码、私钥写进仓库、README、进度文档或日志。

### 播放与媒体
- 播放、暂停、上一首、下一首、拖动进度、音量、静音、倍速。
- 播放队列、随机、循环模式。
- 播放队列管理：播放页队列支持拖动排序、单曲移除与一键清空；移除当前歌曲时自动切换相邻歌曲，清空时停止播放。
- 插件搜索与筛选：对齐桌面版 `Settings/plugins.vue` 的 `filteredPlugins`。移动端插件列表此前既无搜索也无状态筛选，插件装多了只能靠滚动找。现在顶部有搜索框与「全部 / 已启用 / 已禁用」分段控件（`services/pluginFilter.ts`）。搜索覆盖名称、作者、描述、文件名以及**插件提供的音源名**（与桌面版口径一致），多个空格分隔的关键词需全部命中，例如「网易 云」也能找到「网易云音乐」；无结果时给出「清除筛选」入口。
- 插件音源标签：对齐桌面版 `Settings/plugins.vue` 的 `supportedSources` 展示。移动端插件列表此前只有「N 个音源」这个数字，装了多个同类插件时无法从列表分辨谁是谁，只能逐个点进去看。现在每行显示最多 3 个音源名标签，其余折叠成「+N」（`services/pluginSources.ts`）。标签直接读 manifest 的 `contributes.providers` 而不是 `pluginStore.providers`——后者只含已启用插件，而列表需要如实展示已禁用插件声明了哪些音源。
- 音质交集：对齐桌面版 `MusicSourceSection.vue` 的「全局音质（支持交集）」。桌面版允许按音源分别设音质，并给出「所有音源都支持」的交集下拉；移动端只有一个全局 `preferredQuality`（对所有音源生效），所以不需要每源映射，但同样需要交集这个信号——`services/qualityIntersection.ts` 计算所有已启用音源的共同音质（按第一个音源声明顺序、大小写与空白归一化），首选音质下拉把这些档位标注为「（通用）」，当保存的值不被全部音源支持时，说明文字会补一句「N 个音源不支持该音质，切换到它们时会自动降级」。提示只在真的会降级时出现。
- 歌单统计：对齐桌面版 `Settings/PlaylistSettings.vue` 的「播放列表统计」，歌单页头部此前只显示「N 首」，现在补上**总时长与歌手数**（`services/playlistStats.ts`）。时长同时吃结构化 `durationMs` 与旧接口的 `interval` 字符串（`"05:41"`、`"1:05:41"`、毫秒数字串都支持），因此导入歌单与云端歌单表现一致；无法识别的值按 0 计，一首脏数据不会让整单统计变成 NaN。歌手名按 `/ 、 & ， ·` 与结构化数组两种来源去重计数。
- 播放队列导出与导入：对齐桌面版「播放列表管理」（`Settings/PlaylistSettings.vue`）的导出/导入能力，移动端此前队列只能拖动、移除、清空。队列标题栏新增「导出 / 导入」，复用与歌单页完全相同的 `.cmpl` 格式（`services/playlistFiles.ts`），因此队列可以在手机与桌面版之间自由搬运。导出会剔除本地文件与已下载副本——它们只存在于本机，带进文件只会变成坏引用——并在提示里说明剔除了几首；导入是**追加**到当前队列，不会打断正在播放的歌。
- 睡眠定时：`services/sleepTimer.ts` 收敛了定时的时间换算，修掉「设置里还在倒计时、播放器其实没在计时」的问题。原先只把分钟数写进设置，真正的截止时间只存在内存里，重启后既不恢复定时、设置页又照常显示上次选的分钟数；任何重建定时的路径还会按「剩余分钟」重新计时，截止时间一路往后推。现在持久化的是**绝对截止时间**：重启后仍在未来就接着走，已经过期则直接丢弃而不是悄悄重来，旧版本只留下分钟数、没有截止时间的存档也会被清掉，避免显示一个并不存在的倒计时。队列拖动排序与清空也已接入洗牌顺序同步。
- 随机播放：`services/shuffleOrder.ts` 对齐桌面版 `globaPlayList` 的 `shuffleOrder` 语义，修掉两处会让随机「看起来开着其实没生效」的问题。其一，洗牌顺序原先存的是**队列下标**，且在每次开始播放、插入队列、宿主队列更新时都被重置成递增序列——打开随机后点任意一首歌，随机就静默失效；现在顺序按**歌曲 key** 保存，并用「长度与成员都对得上」校验决定是否重建，队列没真变就不重洗。其二，下一首原先从剩余项里**再抽一次**，会重复唱同一首、也可能一直抽不到某些歌；现在沿洗牌顺序推进游标（与桌面版一致），循环模式走到末尾才重洗，一轮之内保证听完。上一首同样沿洗牌顺序回退。洗牌顺序随播放状态一起持久化，重启不会把正在听的一轮打乱；旧版本存档没有该字段时丢弃并重洗。
- 音乐库全部播放与历史管理：收藏列表、本地音乐与最近播放支持“播放全部”与“随机播放”，自动将对应列表设为当前播放上下文；最近播放支持“清空记录”（二次确认）与单曲“从记录中移除”。
- 均衡器与高级音效：10 段图形均衡器、低音增强、环绕混响、声道平衡、响度均衡，基于 Web Audio 实时处理，默认关闭并按设置持久化。
- 低音增强快捷档位：对齐桌面端 `Settings/AudioEffectSettings.vue` 的 `applyBassPreset`——桌面版除滑杆外还有「轻度 / 中度 / 重度」三个一键档（3 / 6 / 9 dB），移动端此前只能自己把滑杆拖到目标值。档位表抽到 `services/bassPresets.ts`，界面用分段控件显示；增益正好等于某档时高亮该档，手动拖到 4.5 dB 这类中间值时不高亮任何一档，避免显示一个与滑杆对不上的选中项。
- 均衡器自定义预设：对齐桌面端 `EqualizerSettings.vue` 的预设管理。移动端此前只有八个内置预设和一个用完即弃的「自定义」选中项，调好的曲线重启就没了。现在可以「存为新预设」「保存当前值」覆盖、删除用户预设、把当前预设重置回自身初始值，并按桌面版同一份 JSON 结构（`presets` / `currentPreset` / `gains` / `enabled`）导出与导入配置，因此手机与桌面版之间能互搬。校验集中在 `services/eqPresets.ts`：拒绝空名、内置同名与重名；导入时丢弃内置同名或增益缺失的条目；文件解析不出对象就抛错提示，绝不把「读不懂的文件」当成「清空全部预设」。用户预设单独存于 `ceru-mobile-eq-presets-v1`，与音效状态分键，避免旧存档被新字段撑坏。
- 暂停过渡：对齐桌面版音量渐入渐出，播放与暂停时对音频元素做短程音量渐变，避免起播爆音与硬切；可在设置页关闭；进入「一起听」房间时自动跳过过渡，保证多端同步不被渐变延迟拖偏。
- 无感过渡（智能交叉淡化）：对齐桌面版 `isSeamlessTransition` 的触发时序——进入尾段 15s 观察窗口后以 100ms 采样平均 RMS（10 帧滑动平均），安静时刻（RMS < 0.04）可从剩余 13s 起触发，剩余 12s 保底、剩余 8s 兜底；过渡时长按剩余时间夹取 6–12s，256 点等功率曲线（`cos²+sin²=1`）由 smoothstep 扭曲，保持响度恒定。移动端只有一条播放链路（单例 `<audio>`），因此沿用桌面版「提前翻转槽位」语义：进入窗口时先把旧歌预载到临时尾巴元素，触发时同一帧把声音交接到尾巴（尾巴静音起播，交接时同步到当前音量，不重叠也不断声），随后才装载新歌——装载期间旧歌由尾巴继续播放，网络慢也不会出现空档；新歌就绪后开始等功率包络，旧歌在尾巴上淡出并在结束后销毁。过渡期间进度条、歌词、媒体会话与队列立即指向新歌；单曲循环、列表末尾、一起听房间内均不触发；关闭开关、暂停/停止、手动切歌、seek 离开窗口都会取消并回收。RMS 观察只借用可视化/鼓点已有的分析节点，拿不到时返回 Infinity，于是只有保底时间规则生效，绝不会把「测不到」误判成安静。已知取舍：尾巴元素不接 Web Audio 效果链，淡出中的旧歌尾段不带音效（该段音量本身在归零）。进度条同步显示过渡标记：尾段以斜纹块预告「可能发生过渡」的区间（由曲目时长算出，关闭开关或曲目过短时隐藏），交接完成后在新歌开头标出淡入段并在淡化时长 + 8 秒后自动清除；过渡进行中还显示「正在平滑过渡」浮层提示，取消或完成时一并收起。
- 音质显示与切换：对齐桌面版音质展示与切换语义。新增 `services/qualityNames.ts` 作为显示名映射（`128k→标准`、`320k→超高`、`flac→无损`、`hires→高清臻音`、`atmos_plus→全景增强`、`master→超清母带` 等）、说明文案、选项构建与本地文件音质兜底的唯一权威实现（对应桌面版 `common/utils/quality.ts` 的 `DISPLAY_NAME_MAP`、`MusicSourceSection.getQualityDescription` 与 `MusicCache.qualityOptions`）。设置页「首选音质 / 缓存音质上限 / 下载音质」三个下拉不再硬编码，改为按已启用插件声明音质的并集（沿用清单顺序，低→高）生成，无插件声明时回落原有四个常见音质；已保存但当前插件不再声明的音质会并入选项末尾，避免下拉空白；首选音质行展示对应说明文案。「缓存音质上限」补上了此前缺失的 `@ionChange`（原来只有单向 `:value`，选不动）。播放页音质按钮显示中文名，本地/已下载曲目按桌面 `canSwitchQuality` 隐藏；选择面板标出当前项，切换后经 `player.reloadCurrentTrack()` 重载当前曲目——先失效已解析地址缓存（否则会复用旧音质 URL），再按 `startPositionMs` 保留进度与播放状态，元数据就绪后自动 seek。歌曲行按桌面 `SongVirtualList` 补上音质标签（取最高可用音质，本地文件按无损扩展名推断）。
- 封面缓存：对齐桌面版 v2.2.0「封面也纳入缓存：下载后落盘，下次播放直接读本地」（`CoverCache.ts`）。移动端此前完全依赖 WebView 自身的 HTTP 缓存，而图片 CDN 的下发缓存期通常很短，旧歌单放久再打开就会退回音符占位图——桌面版正是为修这个问题才做的落盘缓存。现在 `services/coverCache.ts` 提供内存 LRU + IndexedDB `covers` store（数据库版本 1→2，增量迁移，不动既有数据），`CoverImage` 先查缓存再回落网络地址，并在首次加载后静默存一份。只缓存远程 http(s) 图片（`data:`/`blob:`/本地路径跳过），单条上限 2 MB，整体超过 120 MB 时按最久未用淘汰。
- 全局背景壁纸：对齐桌面版 `settings.globalBackground`，在「设置 → 外观」新增独立分组，支持开关、选择/更换/移除本地图片或视频、不透明度（0–100%）、模糊度（0–50px）与亮度（0–200%），并持久化到设置。壁纸文件复制到 App 数据目录 `wallpapers/`（网页预览改为压缩后的 data URL，并拒绝浏览器端视频壁纸），更换或移除时清理旧文件；`components/GlobalBackground.vue` 以固定负层级图层铺满全屏，`html.has-global-background` 把页面外壳（背景、卡片、标签栏）改为半透明并给标签栏加毛玻璃，播放器保留自身封面深色底；移动端独占字段，不参与云端设置同步。
- 沉浸色歌词与歌词模糊：播放页采样当前封面（100×100 画布 + 确定性 K-means 聚类）得出主色调，并按桌面版规则向白色提亮 20% 作为当前句歌词色，可关闭改用纯白；歌词模糊按与当前句的距离非线性递增（最近 1.2px、上限 8px），支持独立开关。
- 跳动歌词：对齐桌面版「跳动歌词」开关，当前行按行长时间换算幅度（时长夹取 100–800ms，缩放 1.02–1.15 倍，上浮 0~0.01em，动画时长不低于 1.1s），起跳用 ease-out、回落用桌面版同款物理回弹曲线 `cubic-bezier(0.34, 1.3, 0.64, 1)`；与「歌词动效」的光晕互不覆盖，可独立关闭。
- 跳转时逐行错开：对齐桌面版 `isSeekLyricStagger`（桌面走 AMLL 的 `LayoutReasonStrategyMap[Seek].disableStagger`），播放页把同一意图落在歌词行过渡延迟上——距新当前句越远延迟越大（28ms/行，最多 8 行）；只在识别到跳转（回退或跨越一行以上，如拖动进度条、点歌词、锁屏快进/快退）后的一小段窗口内生效，其余时间歌词同步过渡，避免拖动时持续拖影。
- Apple 风格歌词：对齐桌面版 `useAmlLyricRenderer`，沿用桌面版 LyricAdapter 的「亮暗双色遮罩」技法（220% 宽渐变遮罩 + `mask-position` 推进），当前句按行时间线性扫过，未唱部分保持 0.3 透明度；移动端歌词只有整行时间轴，因此把桌面版的逐字推进等价为整行推进；与跳动歌词、歌词模糊、逐行错开可叠加，也可单独关闭回落普通样式。
- 音频可视化：播放页以封面主色绘制对称频谱柱，复用均衡器同一条 Web Audio 链路（在链路末端挂载 AnalyserNode），fftSize 按柱数向上取 2 的幂并封顶 2048，柱高使用桌面版 0.6 gamma，30fps 节流；跨域直链无法取样时自动切换为桌面版同款合成波形，开启音效后自动改用真实频谱。
- 自动隐藏控制栏：播放中 3 秒无触控/滚动后，播放控制与底部操作栏淡出并禁用点击，任意点击或滚动立即恢复；打开队列、评论、歌词微调/分享/导出等浮层或暂停播放时不会隐藏；与桌面版一样可按设置关闭。
- 播放器样式切换：新增「经典黑胶」与「沉浸封面」两种布局，黑胶模式带唱片纹理、封面标签、中心孔与随播放状态摆动的金属唱针，播放时唱片 33s/圈匀速旋转，暂停即停；封面模式使用大圆角封面与封面取色光晕；选择结果持久化并在设置页顶部分段控件内切换。

### 文件与导入
- 本地音乐导入。
- 本地音乐扫描过滤：支持按文件大小（默认 100KB）与时长（默认 30s）两层过滤短音频与系统提示音，设置页提供自定义阈值与“不过滤”选项，扫描与 SAF 文件夹导入自动反馈导入与过滤数量。

- SAF 导入跳过原因：`importLocalFile` 原先对「重复文件」与「被时长过滤」都返回 `null`，调用方分不清，于是 `filteredDuration` 永远是 0，界面只能笼统报「跳过/过滤」——用户看不出过滤规则到底有没有生效，也分不清某首歌到底是「本来就有」还是「被判太短」。现在导入会带回原因（`size` / `duration` / `duplicate`），文件夹导入分别统计，结果提示里「已存在 N 首」与「过滤 N 首」分行说明。
- Android SAF 下载目录。
- 下载管理与批量操作：支持下载全部暂停、全部开始、清空队列（含部分已下载临时文件清理）与清空失败/取消记录，配套二次确认弹窗。
- 下载文件名模板：`utils/filename.ts` 现在同时接受桌面版的 `%t/%s/%a/%u/%d/%q` 与移动原有的 `{title}` 写法。此前移动端只认花括号，且没有平台与日期字段——把桌面端的模板搬过来会得到一个满是字面 `%t` 的文件名。`%u` 取音源名（缺失时回落音源 id），`%d` 为当天日期（`YYYY-MM-DD`），未知的 `%x` 原样保留；设置页的模板说明也改成列出真实可用的占位符。
- 下载队列补位：`services/downloadPump.ts` 把「现在该拉起哪些任务」抽成纯函数。原先并发位只在任务完成或失败时才重新评估，于是**暂停或取消一个正在下载的任务会白白空出一个位置**，队列里剩下的歌要等下一次有任务结束才动；「全部暂停」后再「全部开始」最明显——只有前 N 首会重新跑。现在暂停、取消、恢复、删除任务以及修改并发数之后都会统一补位，按队列顺序拉起直到占满空闲位置。
- 下载标签写入：对齐桌面版 `tagWriteOptions`，把原先单一的 `downloadWriteTags` 开关拆成「基础信息 / 封面 / 歌词 / 单独下载歌词文件 / 歌词导出格式」五项，设置页「下载与存储」逐项可调。此前只有布尔开关，只写标题、艺术家与专辑——下载时拉到的封面与歌词都被丢弃。现在封面会经过 `CapacitorHttp` 拉取并转 data URL 内嵌到 MP3 / FLAC / M4A；歌词由 `services/tagWriteOptions.ts` 统一序列化，内嵌与外置共用同一份文本；「单独下载歌词文件」在音频同目录写同名歌词，应用私有目录与 Android SAF 两种落点都支持，且内容为空时绝不写空文件。与桌面版 downloadWorker 同口径：封面或歌词获取失败只记警告并跳过，不会把已完成的下载变成失败。歌词格式只提供 LRC 与 TTML 两项——桌面版的 9 种格式依赖 AMLL 内置导出器，移动端未打包该依赖，非交互的下载流程也无法弹出插件转换器；LRC 只保留逐行时间，TTML 额外保留翻译与音译。旧布尔值在读取时迁移为「基础信息」，升级后行为不变，直到用户主动开启更多。
- Android SAF 文件分享。
- iOS 文件分享。
- 本地标签编辑：标题、艺术家、专辑、年份、流派、歌词与封面；ID3 / FLAC / MP4 标签写入。
- 本地歌曲批量在线匹配：自动筛出缺失封面、专辑，或标题/艺术家为“未知”的本地歌曲，按文件名回退构造查询词，经所选音源搜索后按标题+艺术家+时长加权打分（阈值过滤）挑选最佳结果，批量回填封面、歌词与缺失的身份字段；已存在的人工标签不会被弱匹配覆盖；匹配过程复用全局进度浮层实时显示进度，单曲失败只计入未匹配，不中断整批任务，结束后汇总已匹配数量。

- 分享链接的引用归属：`sharing.create` 校验了 `sharing.publish` 授权，却接受任意歌曲引用——插件可以伪造一条指向别的音源、甚至只是猜出来的 id 的分享链接，再当正经链接交给用户。现在引用同样走播放与下载用的归属校验：必须指向本插件声明的 provider（带 `pluginId` 时必须是自己）。
- `ui.closeView` 的越界回退：插件调用 `ui.closeView` 时此前**无条件** `router.back()`。如果用户早已离开插件页面（自己返回了，或慢操作返回时插件才补发关闭），这一下会把用户从正在看的歌单/设置页弹出去，表现得像应用自己在乱跳。现在只有当路由确实是**本插件的** `plugin-surface` 页面时才回退。
- 插件弹窗与 toast 的文案限长：`ui.confirm` / `ui.prompt` / `ui.toast` 此前原样渲染插件传来的字符串。确认框正文过长会把按钮挤出屏幕——用户除了强杀应用没有别的办法关掉；过长的 toast 则会盖住大半个播放页。现在标题限 120、确认正文限 2000、输入框默认值与占位符限 4000/100、toast 限 200 字符。
- 分页列表去重：搜索页、远程歌单页与分享歌单页此前都用 `[...旧, ...新页]` 直接拼接。音源的分页接口在边界上经常重复返回上一页的最后一首，结果是同一首歌在列表里出现两次——而且行的 `:key` 就是 track key，`v-for` 里出现两个相同 key 的节点会让 Vue 的复用逻辑错乱（滚动位置、点击高亮都会跑偏）。`services/listMerge.ts` 保留首次出现的位置、维持原顺序；取不到 key 的条目保留而非静默丢弃。
- 运行时停止时释放文件句柄：`pickedFiles` / `pickedDirectories` 在 `dispose` 时从未清空，每次插件重载（禁用再启用、热重载、更新）都会把上一轮的 `File` 与 SAF 目录引用留到会话结束——iOS 上被选中的文件还可能一直占着安全作用域访问。
- 进度卡片归属与数量：`ui.progress.update/close` 只按 id 查找卡片、**不校验归属**——卡片 id 可预测，任何插件都能改掉或关掉别的插件（乃至宿主自己的批量匹配）的任务卡片。现在两者都要求调用方的插件 key，宿主自建的卡片不接受插件操作；界面上用户点的 × 走单独的 `dismissPluginProgress`。同时限制单个插件最多同时挂 8 张卡片（超出丢最旧）并对标题/文案限长，避免插件循环创建却从不关闭把界面刷满。
- 插件导航：`ui.navigation.open` 此前忽略 `ref` 与 `sectionId`，把 `library` 映射到歌单页，**未识别的页面一律静默跳到发现页**——插件请求打开「排行榜」或「下载」时落在别处，还以为导航成功了。现在用 SDK 的 `assertNavigationRequest` 校验（页面白名单、query 长度上限、`sectionId` 必须由本插件声明），并逐页映射到真实落点：`playlist` 带上引用打开远程歌单，`charts` 去发现页，`downloads` / `account` 各自打开对应页面。
- 插件收藏未入库的曲目失败：`addHostFavorite` 用 `getTrack(key)` 解析插件传来的实体，取不到就**静默返回**。插件收藏的往往是自己刚搜出来、还没进过本地的歌，于是调用「成功」、收藏列表却毫无变化。现在取不到时按实体自身的元数据构造 Track（与播放路径 `rawEntityToTrack` 同口径）；引用本身不合法则抛错，而不是假装成功。
- 下载任务 id 校验：`downloads.pause/resume/cancel/retry/reveal` 此前把插件给的 id 数组直接交给 store，不存在的 id 会被**静默跳过**——插件以为操作成功，用户却看不到任何变化。桌面版对每个未知 id 抛「下载任务不存在」。现在调用前统一校验（非空字符串、每个 id 必须存在、单次最多 200 个），插件拿到的是诚实的错误。
- 插件自更新：`ui.pluginUpdate.request` 此前只弹一句「请重新导入新版插件文件」，插件在移动端无法自助升级。现在与桌面同口径：只接受不含凭据的 HTTPS 地址，先展示版本号与更新说明让用户确认，再走 `updateFromUrl`（校验 manifest id 未变、并按新声明核对旧授权），返回 `{ accepted, updated, version }`。
- `localMusic.list` 与 `history.list` 的分页：两者此前**完全忽略游标**，每次都返回全量并不带 `nextCursor`。写标准「while (nextCursor)」循环的插件会一次性吞下几千条记录；写「翻到空数组为止」的插件则永远翻不完同一页。现在按不透明偏移游标分页（`services/plugin/paging.ts`），页大小有上限（插件传 0 不会被夹成「每页 1 条」，而是回落默认 100），最后一页不带 `nextCursor`，游标被篡改时直接报错而不是静默从头开始（否则就是死循环）。
- 插件删除歌单内私有歌曲失败：`removeHostTracks` 按 `providerId:id` 拼歌单 key，但插件**私有资源**的 key 是 `pluginId:providerId:id`（`makeTrackKey` 的规则）。这类歌曲在歌单里永远删不掉——插件拿到 `removed: 0`，列表毫无变化，也没有任何提示说明原因。现在候选 key 覆盖两种形状以及实体自带 key，匹配逻辑抽在 `services/playlistKeys.ts`；真的删掉内容时才发 `library.changed`，清空空歌单也不再做无谓的写入与广播。
- 队列版本号：`queue.get` 原来用「队列长度 + 当前索引」拼 `revision`，拖动排序后两者都没变，插件轮询时永远发现不了变化；而推送 `queue.changed` 用的是 `Date.now()`，既不保证严格递增，也和 `queue.get` 返回的值对不上，插件按「revision 变了才刷新」判断时会漏掉更新。现在两条路径共用一个只增不减的计数器，每次队列变更都 +1，与桌面 `markPluginQueueChanged` 生成新 revision 的语义一致。
- 导出文件的权限与路径边界：`files.saveText` 此前**不校验任何权限**（readText / readBase64 / writeText 都有），而且把插件给的 `suggestedName` 原样拼进 `exports/<name>`——传 `../../library.json` 就能写到 `exports/` 之外、覆盖应用目录里的其它文件；`files.writeText` 也能凭 `id` 句柄写任意路径。现在 `saveText` 要求 `files.write`，文件名收敛成单个经过清洗的 basename（去分隔符、控制字符、前导点，限长 120），`writeText` 只接受 `exports/` 下的句柄。桌面版走系统保存对话框，本来就没有这个问题。
- 系统通知单独授权：`ui.notify` 在 App 处于后台时会真的发系统通知，此前**不校验任何权限**——任何插件都能往用户的系统通知栏写条目。SDK 里 `notifications` 组的唯一权限就是 `notifications.system`，现在后台路径要求它；前台仍只是应用内 toast，不离开 App，因此不需要额外授权。
- 局域网访问单独授权：桌面端 `requestNetwork` 带 `allowPrivate` 回调，只有插件**声明并获批 `network.private`** 才允许访问本机/内网地址；移动端此前只查 `network.request`，插件可以扫描 `127.0.0.1`、`192.168.*`、`*.local` 以及用户家里的其它内网设备——而 WebView 本身往往就在同一局域网内。现在 `http.request` 与 `sockets.connect` 在目标落在内网范围时要额外授权；分类覆盖 RFC1918、回环、链路本地、CGNAT、IPv4-mapped IPv6 与 mDNS/局域网后缀，无法解析的地址按「私有」处理（宁可拒绝）。同时修复 worker 未把 `permissionKey` 透传给宿主、导致局域网请求无法解析授权的问题。
- 插件存储的键与大小校验：`storage.get/set/delete` 此前把插件传的键直接拼进 IndexedDB 主键，不校验长度、控制字符，也不挡 `__proto__` / `constructor`，写入值更没有大小上限——一次超大写入会撑大与歌单、下载、本地曲目共用的数据库，拖慢甚至拖垮全部读写。现在键限 1–256 字符、拒绝控制字符与原型链特殊名，单键值按 JSON 序列化后不得超过 10 MiB（与桌面 `PluginStorage` 同口径），不可序列化的值直接拒绝而不是存成 `undefined`。
- 插件升级后核对旧授权：授权原本按 `[pluginKey][permissionKey]: true` 存，只认 key。插件升级若保留同一个 key、却把它改成指向别的权限，旧授权会被直接继承——用户当初同意「读取设置」，升级后等于同意了「控制播放」。桌面版用 `key:name:scope` 指纹避免这一点。现在授权时一并记录权限名，插件导入/更新时与新声明核对：名字对不上或该 key 已被删除的授权一律撤销、要求重新确认；旧存档里只有 `true` 的条目在其 key 仍被声明时保留并补上名字（下次升级就有得比对）。
- 权限声明校验：`requirePermission` 此前只查「这个 key 有没有被授权」，从不查插件**是否在 manifest 里声明过**它。插件可以随手造一个 key，用户会看到一个没有理由说明的授权框，同意后该能力就此打通——既绕过声明，也让用户在不知情下授权。现在先核对「key → 声明」且声明名必须是正在使用的那个能力（声明的读权限不能拿去要控制权限），再去询问用户；`permissions.request` 同样拒绝未声明的 key（否则可以先授权再调用）。权限名统一改用 SDK 的规范名（`player.control`、`library.write` 等），中文文案集中在一张表里，逻辑抽到 `services/plugin/permissions.ts` 便于单测。
- 子插件、外链与歌单导入的授权：`guests.*` 此前**没有任何权限校验**——任何插件都能导入、启用、删除、调用子插件（子插件是嵌在插件里运行的第三方脚本，风险更高）；`app.openExternal` 不限协议也不校验；`ui.playlistImport.open` 只凭插件传值就建歌单，连用户确认都没有。现在 `guests.import/select/remove` 要 `guests.manage`、`guests.invoke` 要 `guests.run`；`app.openExternal` 要 `external.open` 且只放行不含内嵌凭据的 http(s) 地址；`ui.playlistImport.open` 只接受插件**声明过的**导入器、限制参数长度，并弹出输入框让用户确认后再导入。
- 设置与本地音乐 RPC 的授权：同一处缺口的最后两块。公开设置白名单挡住了密钥类字段，但没有任何东西阻止插件改用户的播放设置；`localMusic.*` 更是完全不校验，插件可以直接列出本机音乐库、甚至改写音频文件里的标签。现在 `settings.get/update` 要 `settings.read`/`settings.write`，`localMusic.list/scan/getTags` 要 `localMusic.read`、`writeTags` 要 `localMusic.write`，与桌面分发处一致。
- 收藏 / 历史 / 下载 / 歌单 RPC 的授权：同一处缺口——这几个服务此前也不校验插件传入的权限键，插件可以不经询问就增删收藏、发起下载、甚至清空用户歌单。现在按桌面口径逐项要求 `library.read` / `library.write` / `library.delete`（历史读走 `player.read`）、`downloads.create` / `downloads.manage`；可收藏与可下载的歌曲引用必须属于插件自己声明的 provider，单次下载限制 1–100 首，歌单导入只接受标准歌曲引用（否则插件私有结构会被写进用户歌单）。
- 播放与队列 RPC 的授权：`services.player.*` / `services.queue.*` 此前**完全不校验权限**，任何插件都能暂停用户的音乐、改音量、甚至用 `queue.replace` 换掉整个队列；`queue.append/replace` 也不校验歌曲归属，插件可以把别的音源的歌塞进队列。现在 `getState` / `queue.get` 要 `player.read`，其余要 `player.control`；带 track 引用的操作还要求该引用属于本插件声明的 provider（带 `pluginId` 时必须是自己），与桌面 `PluginHost.ownedRef` 一致。规则抽在 `services/plugin/ownership.ts`，无需启动 Worker 即可单测。
- 一起听房间内队列只读：房间里的队列由服务端广播、房主/管理员改动；普通成员在播放页拖动或移除，会在下一次 `queue:update` 时被覆盖回去，表现为「拖了一下又弹回」。桌面端 `PlaylistDrawer` 在 `lt.isInRoom && !lt.canControl` 时直接禁用拖拽与移除，移动端此前没有任何防护。现在播放页队列在同样条件下禁用排序与移除、隐藏拖动手柄、阻止清空，并给出一行原因说明。
- 插件能力表如实标注：`capabilities.list` 此前把所有服务都标成 `available: true`，包括手机上没有意义的 `window.control`（最小化/最大化/迷你播放器）以及 iOS/Web 上的 `files.pickDirectory`——插件据此调用只会撞上「未实现的 Host RPC」。现在 `window` 标为 `unsupported`，`pickDirectory` 只在 Android SAF 能真正支撑该句柄时出现在方法列表里，插件可以先看 `available`/`methods` 再决定是否调用。
- 插件目录选择与按目录扫描：`files.pickDirectory` 此前固定返回 `null`，`localMusic.scan` 也忽略传入的目录，插件的「导入这个文件夹」流程在移动端完全走不通。现在 Android 上 `pickDirectory` 走 SAF 返回可后续使用的目录句柄（iOS/Web 明确返回 `null`，而不是给一个随后必然失效的假句柄），`localMusic.scan` 解析这些句柄（支持多个目录）后再导入，句柄过期会明确报错要求重选。同时给 `files.readText/readBase64/writeText` 补上 `files.read` / `files.write` 授权校验——与桌面 `handleFileService` 一致，此前这些调用**不校验任何权限**，插件只要拿到句柄就能读写文件；「选文件」本身仍不校验，因为那是用户在系统面板里主动点的。
- 队列定位当前播放：对齐桌面端 `PlaylistDrawer` 的「定位当前播放」。移动端队列是长列表，划走之后没有回到正在播那一行的办法。现在队列头部有「定位」按钮；滚动用的是队列自己的滚动容器（不是 `scrollIntoView`——后者会把整个弹层一起滚，导致错位）。
- 播放页睡眠定时可选时长：播放页的更多菜单此前只有「15 分钟后暂停」一个硬编码选项，想听半小时得退出播放页去设置页改。现在直接给出 15 / 30 / 60 分钟三档（与设置页同一组时长），已开启时显示「关闭睡眠定时」。
- 下载文件名模板预览：对齐桌面端 `StorageSection.vue` 的 `formatMusicInfo(template, previewSongInfo)`。移动端此前只显示模板原文，`%t` 误写成 `%T`、或漏了分隔符，要等下完几百首才发现文件名全一样。现在用一首示例歌实时预览（`utils/filename.ts` 的 `buildDownloadFilename`），两种写法（`%t` 与 `{title}`）都走同一条渲染路径，因此预览结果与实际落盘名一致。
- 已完成下载可重新下载：已完成的下载任务此前只有播放、分享、删除记录——文件损坏或想换音质重下时，只能先删记录再回去找歌。现在补「重新下载」：先删掉旧文件再入队，否则 `resolveDownloadPath` 发现同名文件存在会写成「歌名 (1).mp3」，点一次反而多一份重复文件；代价是重下失败时旧文件已删，但任务仍在列表里可再次重试，比悄悄堆重复文件更诚实。
- 插件日志可复制与清空：插件详情页的「最近日志」此前只读——手机上遇到插件报错，唯一的办法是照着屏幕手打一遍；上一轮会话的旧日志也永远排在最前面。现在有「复制全部」（每行带时间与级别，可直接贴进 issue）与「清空」（先确认，**只清这个插件**的日志，不动其它插件）。
- 歌单上传 / 同步到云端：对齐桌面端 `music/list.vue` 的「上传到云端」「同步到云端」。移动端此前只有分享面板会隐式上传云端，用户无法主动备份或更新云端副本，也不知道覆盖了云端的什么。现在歌单菜单按是否已有 `cloudId` 自动显示「上传到云端」或「同步到云端」，操作前确认并说明影响：同步会用本机内容**覆盖云端副本**（其它设备的改动会被替换），上传只包含在线歌曲、本地文件与已下载副本不会上传；整单都是本地文件时直接拒绝。
- 歌单列表搜索：收藏与本地歌曲早就有搜索栏，歌单网格却没有——歌单攒到几十个时只能一路划过去找，还得绕过「新建歌单」卡片。现在按名称与描述过滤，且只在歌单多于 5 个时显示搜索栏，小歌单库不为此多一条横栏。
- 歌单列表操作补齐：音乐库歌单卡的菜单此前只有「重命名 / 删除歌单」，而删除是一点即删、没有任何确认——这是全应用唯一一个没有二次确认的破坏性操作。现在补上「打开歌单」「分享歌单」（复用歌单页的分享面板，此前从列表页完全够不到），删除前先确认并说明歌单内的歌曲不会被删。
- 远程歌单保存到本地：对齐桌面端 `music/list.vue` 的「保存到本地」。移动端此前对插件/排行榜的远程歌单只能播放与批量下载，没有整单收藏的入口。现在远程歌单页有保存按钮：**先补拉完所有分页再保存**（否则只会存下当前可见的一页，用户以为存了整单），同名本地歌单直接拒绝而不是静默重名或覆盖，新建后带远程封面并跳转到新歌单。
- 强调色色板无障碍：设置页六个强调色圆点是纯色按钮，没有文字也没有 `aria-label`，读屏只能念出六个无名按钮、也听不出当前选中哪个。现在整体作为 `radiogroup`，每个圆点是带色值的 `radio` 并暴露 `aria-checked`。
- 强调色同步到 Ionic 色组：设置页换强调色时只写了 `--ceru-brand`，而 Ionic 的按钮、开关、进度条、分段控件只认 `--ion-color-primary*`，于是选了非青绿色后界面同时出现两套强调色。`services/accentTheme.ts` 按 Ionic 官方 palette 的规则（12% shade、10% tint）生成整组 primary 变量，并用 WCAG 亮度挑对比文字色，浅色强调色（如黄色）上不会出现看不清的白字；非法颜色值直接跳过，保持主题默认。
- 歌单附件封面兜底：对齐桌面端 `community/usePostAttachmentCover.ts`。附件既没自带封面也没有预览图时（老帖子、预览为空），桌面版会按云端歌单取第一首的封面，移动端此前直接不渲染附件卡片，带歌单的帖子看起来像纯文字。现在同样按 `listId` 补一次封面，并做了两件信息流里必须做的事：同一歌单结果缓存（**失败也缓存**，否则滚动时会反复重试一个拿不到封面的歌单），以及用「请求中」集合避免一次渲染发出多个重复请求。
- 无图帖子文字封面：对齐桌面端 `community/TextNoteCover.vue`。桌面版给没有配图的帖子按帖子 id 稳定生成一张「音乐随记」卡片（四套版式 × 六组配色，同一条帖子列表/详情/下次打开都一致）；移动端此前只有一段纯文字，信息流看起来像聊天记录。配色、版式、角度与种子规则与桌面版完全一致（`services/noteCover.ts`），正文沿用桌面版 60 字截断；**不引入**桌面版打包的 7 款中文手写字体（约 17 MB），改用系统楷体候选，拿不到时回落 serif——为一张装饰性封面加 17 MB 安装包不划算。
- 社区歌单附件可打开：帖子里的歌单附件此前只弹「将在后续云歌单功能中打开」，实际上永远打不开。附件虽然只存云端 `listId` 与前三首预览，但云端接口能取回全量曲目——`services/cloudPlaylistTracks.ts` 把云端歌曲按歌单页同一套 ref/音质规则映射成 `Track`，点一下即整单入队并从第一首可播放的歌开始播，完整列表可在播放页队列看到；对应音源插件未安装时歌曲保留在队列里但标为不可播放，而不是让人以为歌单是空的。
- 社区发帖附加歌单：对齐桌面端 `community/PostCreateDialog.vue` 的「分享音乐」。移动端发帖此前只能「附加正在播放」的单曲，没有任何分享歌单的入口。现在发帖页有「分享歌单」，列出已同步到云端的歌单（没有云端 ID 的歌单服务端解析不了，发出去是点不开的卡片，因此不列）；附件只包含可分享的在线歌曲，本地文件与已下载副本会被剔除，若整单都是本地文件则拒绝并说明原因，而不是发一张空卡片。附件组装与展示文案抽在 `services/postAttachment.ts`。帖子编辑页此前会把原附件读进 `editAttachment` 却从不渲染，用户既看不到附了什么歌，也删不掉——现在编辑页显示附件卡片并可移除，展示文案与信息流卡片共用同一份规则。
- 官方通知卡片：对齐桌面端 `notifications/NoticeCard.vue`。移动端此前把 `notice` 类消息和点赞/回复画成同一种两行卡片，markdown 公告被压成一句截断文本，`iframe` 类通知只显示成一段无意义的文字。现在官方通知单独用 `components/NoticeCard.vue` 渲染：markdown 正文解析成标题/列表/段落与行内粗体、斜体、行内代码、链接（`services/noticeContent.ts`），内容长时给「展开全文」；`iframe` 类型不内嵌（WebView 里第三方页不能滚动、不能跳转），改为「打开网页内容」，外链统一用系统浏览器打开。**渲染方式是模板插值而不是 `v-html`**——桌面版用 marked + DOMPurify，移动端没有这两个依赖，与其引入解析器加过滤器，不如根本不生成 HTML 字符串，从而没有注入面；链接只放行 http(s)，`javascript:` 一类的标记退化为纯文本。
- 消息中心手动刷新与清理确认：桌面版消息中心有独立刷新按钮，清理已读前会二次确认。移动端原来只在进页时加载，实时连接掉线后没有任何手段拉一次；「清理」按钮点一下就直接调接口，误触不可恢复。现在顶栏有刷新按钮（等在进行中的请求结束再拉，失败给出原因）与「清理已读」确认框（明确只删已读、未读保留），与桌面版文案一致。
- 已完成下载的文件校验：对齐桌面端 `DownloadManager.validateFiles`。用户可能在系统文件管理器里删掉下载好的歌，桌面版在打开「已完成」分页时逐个确认文件仍在，缺失的改判为「文件已删除或移动」；移动端此前从不校验，列表一直显示「已完成」，点播放才报错。现在切到「已完成」分页即校验（`services/downloadValidation.ts`）：只查已完成、有应用内相对路径的任务，跳过 SAF（外部授权目录只有 document URI，无法 stat）；**只有确认为「不存在」才改判**，权限抖动或原生桥接异常视为无法确认并保持原样，避免把整页下载凭空标成失败。改判时同时摘掉歌曲上已失效的下载路径，播放不会再指向不存在的文件。
- 本地歌曲标签编辑器：对齐桌面端 `Music/LocalTagEditor.vue`。移动端此前用 `alertController` 的六个输入框编辑本地歌曲，没有封面预览、没有更换封面入口，长歌词挤在固定高度文本框里，也没有在线搜索。现在换成整页 sheet（`components/LocalTagEditorSheet.vue`）：「编辑信息」页可选/换/移除封面（统一裁正方形并压到 600px），标题、歌手、专辑、年份、流派、歌词逐项可改；「在线搜索」页按当前音源联想，候选的「使用」只填入表单并取回封面与歌词，仍需确认后保存。封面用 `CapacitorHttp` 取字节而不是 canvas——封面 CDN 基本不发 CORS 头，canvas 会被污染；抓不到时保留原封面，绝不把远程地址写进标签（`writeLocalTags` 只会当 data URL 解析）。表单校验与候选合并抽在 `services/localTagEditor.ts`。
- 搜索联想：对齐桌面端 `components/search/searchSuggest.vue`。桌面版输入时弹出「直接搜索：<关键词>」加单曲/歌手/专辑/歌单分组建议；移动端此前只有发现页的纯字符串联想，搜索页本身什么都不给。现在搜索页有同一块面板（`services/searchSuggestions.ts` 归一化三种插件返回形状，按桌面版的组序渲染，单组与总数都有上限以免面板顶掉搜索框），联想走独立请求守卫，快速输入时旧结果不会盖住新结果。
- 均衡器实时频谱：对齐桌面端 `Settings/EqualizerSettings.vue` 顶部的 canvas。移动端音效页此前只有十根滑杆，看不出各频段在做什么。`components/EqSpectrum.vue` 复用播放页的同一个 AnalyserNode（不额外建链路），柱子按对数分布在 20 Hz–20 kHz（线性频段会把低频挤成一根、把高频铺满半屏），区间映射抽在 `services/eqSpectrum.ts`；拿不到分析节点（跨域直链、未起播）时画一条基线并说明，不伪造跳动。
- 识曲片段定位与结果搜索：对齐桌面端 `views/music/recognize.vue`。移动端此前丢弃了识别结果里的 `startTime`，点播放一律从 0:00 开始，和刚听到的那一段对不上；现在结果卡片显示「识别片段 03:12」，播放后 seek 到该处并提示。结果旁补上桌面版的搜索按钮（歌名 + 歌手跳搜索页）。结果归一化收敛到 `services/recognizeResults.ts`：兼容数组 / `items` / `songs` 三种外壳，封面按 `img`/`artworkUrl`/`cover`/`pic` 取，歌手数组与对象展平成「A / B」，小于 1000 的小数当秒处理（12.5 → 12.5s，而不是 12ms），非对象条目直接丢弃。
- 歌单转换器。
- 主题与设置。
- 设置搜索：设置页顶部新增搜索栏，覆盖账户、插件、播放、缓存、歌词、存储、本地音乐、外观、壁纸、工具、关于共 11 个分组；支持中文标题、英文关键词、别名与分组名匹配，空查询展示最近使用（本地持久化、去重、上限 5 条）；支持键盘 ↑/↓/Enter 选择，选中后滚动到对应分组并短暂高亮。索引与最近使用清洗逻辑集中在 `services/settingsSearch.ts`。

## 当前未完成

- 自定义 HTTP/SOCKS5 代理：Android `ProxyController` 与 iOS `WKWebView` 均不允许应用自设代理，原生 HTTP 也只走系统网络栈；移动端只能跟随系统代理，界面上不提供无效开关。自定义 CA 需在系统层面安装。
- 每个 iOS 版本一套 SwiftUI/UIKit 原生控件；当前仍是 Ionic iOS 模式 + `ios-14` … `ios-26` 版本化样式。
- iPad Stage Manager / iOS 原生多窗口完整能力；当前只保证分屏与大窗口布局可用。
- 后端歌单分享的网页在线播放（需服务端解析模块导出）；App 内歌单分享链接创建已支持。
- 无感过渡的尾巴链只在主链已接管音频（音源为 blob/data）时建立；跨域直链时尾巴仍走原生输出，音色可能与主链不同。
- 真机回归仍未系统性完成。

- 未做系统化真机回归。

- iOS IPA 未签名，需要用户重签。
- 插件 WebView 不是操作系统级安全沙箱，只应安装可信插件。
- 缓存、通知、后台播放、SAF 等能力依赖系统行为，需要在多机型上确认。
